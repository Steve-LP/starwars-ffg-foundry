# Star Wars FFG - Character Creation & XP Engine (Architecture Documentation)

This document describes the data structure, rules, getters, and methods governing character creation and XP expenditure in our Foundry VTT V14 module. Any AI assistant or developer working on the UI or sheets should refer to this document.

---

## 1. Data Schema (`system.creation` & `system.xp`)

Defined in `module/data-models.js` under `CharacterData`:

```javascript
creation: new fields.SchemaField({
  isCreationMode: new fields.BooleanField({ initial: true }), // True during creation phase, false once finalized/locked
  startingXp: new fields.NumberField({ initial: 0, min: 0 }),  // Base species XP (e.g., 100, 110)
  baseGroupDutyXp: new fields.NumberField({ initial: 0, min: 0 }), // GM-assigned Group Duty starting XP
  doubleDuty: new fields.BooleanField({ initial: false }), // Checkbox indicating if player doubled starting duty for +10 XP
  baseCharacteristics: new fields.SchemaField({ // Set to species base characteristics during Species drop
    brawn: new fields.NumberField({ initial: 2, min: 1, max: 6 }),
    agility: new fields.NumberField({ initial: 2, min: 1, max: 6 }),
    intellect: new fields.NumberField({ initial: 2, min: 1, max: 6 }),
    cunning: new fields.NumberField({ initial: 2, min: 1, max: 6 }),
    willpower: new fields.NumberField({ initial: 2, min: 1, max: 6 }),
    presence: new fields.NumberField({ initial: 2, min: 1, max: 6 })
  })
}),
xp: new fields.SchemaField({
  total: new fields.NumberField({ initial: 0 }),
  available: new fields.NumberField({ initial: 0 }),
  earned: new fields.NumberField({ initial: 0, min: 0 }), // XP earned from adventure campaigns
  log: new fields.ArrayField(new fields.ObjectField(), { initial: [] })
})
```

## 2. Dynamic Calculations & Getters (on `SWFFGActor` / `actor.js`)

XP is not manually subtracted or updated. Instead, the actor's available XP and total XP are calculated dynamically on-the-fly and populated inside `prepareDerivedData()`.

*   **`dutyXp` (Getter)**:
    Returns the total XP generated by starting duty choice:
    `baseGroupDutyXp + (doubleDuty ? 10 : 0)`.
*   **`maxAttributeXpAllowed` (Getter)**:
    The absolute limit for characteristic upgrades (lifetime cap):
    `startingXp + dutyXp`.
*   **`currentAttributeXpSpent` (Getter)**:
    Calculates total XP spent on attribute upgrades:
    *   Compares the current raw database values (`this._source.system.characteristics`) with the species defaults (`system.creation.baseCharacteristics`).
    *   Upgrade cost for increasing a characteristic from value $B$ to value $C$ is $\sum_{v=B+1}^{C} v \times 10$ (e.g., upgrading from 2 to 4 costs $30 + 40 = 70$ XP).
*   **`calculateSpentTalentXp()` (Method)**:
    Sums up XP spent on all owned talents.
    *   Talents with a `system.row` (specialization-tree talents) cost `(row + 1) * 5` XP.
    *   Standalone talents cost `system.tier * 5` XP.
*   **`totalAvailableXp` (Getter)**:
    Calculates dynamic XP remaining:
    `(startingXp + dutyXp + earned) - currentAttributeXpSpent - calculateSpentTalentXp()`.

### XP Property Binding
In `prepareDerivedData()`, the following bindings are automatically enforced:
*   `actor.system.xp.available` = `actor.totalAvailableXp`
*   `actor.system.xp.total` = `startingXp + dutyXp + earned`

## 3. Backend APIs & Mutation Methods (on `SWFFGActor`)

Always use these asynchronous methods to modify characteristics and finalize character creation.

### `buyAttribute(attributeName)`
Attempts to upgrade a characteristic by 1 rank (e.g., `await actor.buyAttribute("brawn")`).
*   **Cost**: `(currentRawValue + 1) * 10` XP.
*   **Validation Rules (Bypassed if User is GM - `game.user.isGM` is true)**:
    1.  Character must be in Creation Mode (`system.creation.isCreationMode` is `true`).
    2.  Character must have sufficient global available XP (`totalAvailableXp >= cost`).
    3.  Upgrading must not exceed the species ceiling (`currentAttributeXpSpent + cost <= maxAttributeXpAllowed`).
*   **Updates**: Atomically increments `system.characteristics.[attributeName].value`.

### `lockCreation()`
Finalizes character creation:
*   Sets `system.creation.isCreationMode` to `false`.
*   Effectively disables any further attribute upgrades via XP for players.

## 4. UI Hook Recommendations

When building the character sheet UI:
*   **Attribute Upgrades**:
    Show a `[+]` button next to each attribute *only* when `system.creation.isCreationMode` is true. Disable or hide the button if the current user is a player and `totalAvailableXp < cost` or `currentAttributeXpSpent + cost > maxAttributeXpAllowed`. Bind clicking this button to `actor.buyAttribute(attributeName)`.
*   **Duty Tab integration**:
    When `system.creation.isCreationMode` is true, show form fields for:
    *   `system.creation.baseGroupDutyXp` (Number input)
    *   `system.creation.doubleDuty` (Checkbox)
    *   Show a progress counter: `Spent Attribute XP: {{system.currentAttributeXpSpent}} / {{system.maxAttributeXpAllowed}}`.
*   **Creation Phase Finalization Banner**:
    If `system.creation.isCreationMode` is true, show a banner at the top of the sheet with a button "Lock Character Creation" that triggers `actor.lockCreation()`.
